# USAparts.top: аудит індексації, швидкості та вітрини

Дата завершення: 07.09.2026. Базова версія для порівняння: `8504859`.

## Межі перевірки

Бойовий сайт перевірено зовні, без доступу до приватного звіту Search Console,
логів VPS або кабінету Merchant Center. Перевірено індекс sitemap, усі 12 дочірніх
карт та 80 рівномірно вибраних сторінок із 3698 унікальних URL.
Це вибірка бойового сайту, а не підтвердження стану кожного товару.

Усі перевірені бойові карти та сторінки повертали 200. У вибірці не виявлено
noindex або невідповідного canonical. У 7 картках у Product.image була заглушка.
PNG favicon 48x48, 96x96, 192x192 та ICO доступні з 200 і правильним типом.
Robots.txt не забороняє обхід товарів та favicon. Заміна іконки навмання не потрібна.

Виправлення реалізовані в репозиторії та перевірені в локальному Docker/PostgreSQL.
Локальна база має 311 унікальних активних товарів і 342 URL у sitemap.
Це окрема база, а не зменшення асортименту бойового сайту.
Перенесення на VPS та повторна індексація Google не виконані в межах цієї перевірки.

## Знайдені та виправлені причини

- Категорії та бренди показували тільки перші 72 товари без наступних сторінок.
  Тепер усі доступні товари розбиті по 48, з HTML-посиланнями і власним canonical кожної сторінки.
- Видалені товари й неіснуючі категорії перенаправляли на нееквівалентний каталог.
  Тепер вони повертають справжній 404 з корисною сторінкою пошуку.
- Довільні номери сторінок могли створювати зайві URL. Неприпустимі й надмірні
  номери повертають 404; порожні фільтри й page=1 нормалізуються.
- Товари без фото були у sitemap, але ховалися з каталогів. Тепер вони доступні
  через звичайну навігацію. Заглушка залишається в інтерфейсі, але не видається за
  справжнє фото Product у структурованих даних.
- JSON-LD сторінок каталогу описував не ті товари, які бачив відвідувач.
  Тепер ItemList відповідає видимій сторінці.
- У sitemap більше немає штучної щоденної зміни lastmod індексу.
  Карта зображень кешується, XML має ETag і підтримує 304.
- Точний збіг OEM отримує перше місце у внутрішньому пошуку.
  URL товарів, коди, sku та mpn збережені; масової зміни адрес немає.
- Кошик показував базову ціну USD без націнки складу, хоча вітрина показувала UAH.
  Ціни в каталозі, кошику, JSON-LD та Merchant-експорті використовують спільне
  округлення роздрібної ціни; оформлене замовлення зберігає роздрібну USD-ціну.
  Базові ціни та залишки товарів у БД не перезаписуються.

## Швидкодія

Вимірювання Flask test client на тій самій локальній базі: 8 запитів до кожного
маршруту, медіана останніх 7. Це час формування відповіді, не час завантаження
в інтернеті й не показники PageSpeed/Core Web Vitals.

| Маршрут | До, мс | Після, мс | Зміна |
| --- | ---: | ---: | ---: |
| Головна | 58.41 | 13.25 | приблизно 4.4x швидше |
| Каталог | 69.67 | 13.45 | приблизно 5.2x швидше |
| Пошук 09P321361 | 71.16 | 4.49 | приблизно 15.8x швидше |
| Sitemap зображень | 78.76 | 3.18 | приблизно 24.8x швидше |

Кеш нормалізації тексту обмежений за розміром. Одночасні запити не перебудовують
однакові холодні кеші паралельно. Адміністративні лічильники не запитуються на
публічних сторінках. Після успішних змін адміністратора публічний кеш очищається.

Flask development server замінений на Waitress: один процес, 8 потоків,
зі збереженням поточних фонових задач та логіки reverse proxy.
HTML не поміщається у спільний кеш, щоб не змішувати сесії й кошики відвідувачів.
Текстові публічні відповіді стискаються gzip, якщо клієнт його підтримує.

Для локально завантажених фото створюються кешовані WebP-мініатюри 320/640/960.
Оригінали збережені. URL зовнішніх фото не проксіюються й не завантажуються
масово на сервер. Їхня швидкість і доступність залежать від зовнішнього джерела.

## Дизайн і перевірки

Нова світла вітрина: читабельний контраст, виразний OEM, ціна в гривні,
коротка навігація, підбір авто/категорії, компактний футер з політиками й контактами.
Шапка знаходиться у звичайному потоці сторінки, а не перекриває мобільний екран.
Головна й каталоги більше не завантажують великий адміністративний CSS.
Адреса нового CSS автоматично змінюється за хешем вмісту після оновлення.
Шрифт Manrope розміщений локально з ліцензією OFL.
Плаваючий віджет Trustpilot прихований на телефонах і під час відкритих діалогів,
щоб не перекривати форми. Відгуки в картках товарів не видалені.

- 15 регресійних тестів пройшли у Docker.
- Повний обхід 342 локальних URL: немає помилок у реалізованих перевірках HTTP,
  XML, canonical, noindex, title/description/H1 та структури JSON-LD.
- Перевірено головну, каталог і товар при ширинах 320, 390, 768, 1440 px:
  горизонтального переповнення немає.
- Через браузер перевірено підбір категорії, другу сторінку категорії, додавання
  та видалення товару в кошику, мобільне вікно оформлення і збільшення фото.
- Тест оформлення замовлення ізольований від БД, списання товарів і Telegram.
  Реальне замовлення не створювалося; доставка через API перевізника не перевірена.

## Що залишається поза кодом

1. Розгорнути перевірену версію на VPS з резервною копією поточних даних.
   Потрібна перебудова web-образу через наявний процес Portainer, а не тільки
   перезапуск старого контейнера. Не видаляти volumes PostgreSQL/uploads.
2. Після розгортання перевірити головну, товар, пагінацію, кошик, robots.txt і sitemap
   на публічному домені. Оновити товари/ціни Merchant після узгодження роздрібного
   округлення: для складів з дробовою націнкою можливі невеликі зміни показаної ціни.
3. У Search Console перевірити кілька кінцевих URL товарів із різних складів і
   повторно подати основний sitemap. Не надсилати на індексацію кошик та результати пошуку.
4. Для товарів Merchant потрібні реальні фотографії. Заглушка чи вигаданий рейтинг
   не є виправленням вимог Google. Додати відсутні фото та точні характеристики.
5. Перевірити в Search Console статистику сканування і в логах VPS 5xx, тайм-аути,
   час відповіді Googlebot. Після розгортання потрібні польові показники швидкості.
6. Окремо виправляти блокування Merchant Center щодо бізнес-інформації: технічні
   SEO-зміни самі по собі не знімають блокування облікового запису.

"Сторінка з переспрямуванням", noindex кошика/пошуку та правильно канонікалізовані
дублікати не потрібно перетворювати на індексовані сторінки. "Виявлено, наразі не
проіндексовано" не встановлює одну конкретну помилку коду. Наявність sitemap,
статус 200 та валідна розмітка допомагають обходу, але не гарантують індексацію.

## Відтворення перевірок

Команди виконуються з кореня цього репозиторію, на локальному тестовому Docker:

```powershell
docker compose up -d --no-deps --build web
docker cp tests/test_storefront.py usa_auto_parts_v3_web:/tmp/test_storefront.py
docker exec -e PYTHONPATH=/app usa_auto_parts_v3_web python /tmp/test_storefront.py -v
docker cp tools/site_audit.py usa_auto_parts_v3_web:/tmp/site_audit.py
docker exec usa_auto_parts_v3_web python /tmp/site_audit.py --base http://localhost:8080 --sample 0 --delay 0.02
docker cp tools/benchmark_storefront.py usa_auto_parts_v3_web:/tmp/benchmark_storefront.py
docker exec -e PYTHONPATH=/app usa_auto_parts_v3_web python /tmp/benchmark_storefront.py
```

Для обережної вибіркової перевірки бойового сайту:

```powershell
docker exec usa_auto_parts_v3_web python /tmp/site_audit.py --base https://usaparts.top --sample 80 --delay 0.2
```

JSON-звіти з перевіреними URL збережені локально в `artifacts/`, не містять ключів
або паролів і виключені з Git. Автоматичний аудит не замінює Rich Results Test,
перевірку доступності checkout та приватні звіти Google.
